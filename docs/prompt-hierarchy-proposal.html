Prompt Hierarchy — Design Proposal v2

Revised after BCBA review. Simplified to one prompt level per goal, per session.

Revision 2 · Design approved by BCBA Sep 27, 2026 · detailed rulings pending

What changed from v1 — and why

v1 asked the RBT to choose a prompt level on every trial: roughly 40 seven-way decisions per session, during live therapy. Tatiana's review: too complex and too long for the therapist. Agreed — that design fails in a predictable way, with RBTs defaulting to one value or filling it in from memory afterward, producing a column that looks rich and isn't. v2 records one prompt level per goal per session — 5 to 8 decisions instead of 40. The per-trial ✓/✗ scoring stays exactly as it is today. Nothing else in the session changes.

What the field means — please confirm

"One level for the goal" can mean three different things, and they are not interchangeable. If the rule isn't written down, one RBT will record one meaning and another will record a different one, and the column stops being comparable across therapists — which is worse than not collecting it at all.

ReadingWhat it recordsAssessment
A. Target level RECOMMENDED The support level this goal is programmed to run at this session — "G12 is being run at Gestural this week." Unambiguous, checkable against the program book, and it makes the one-level-per-goal assumption true by definition rather than an approximation.
B. Most intrusive usedThe highest level of support needed at any point.Defensible, but biases the record toward more support than was typical.
C. Typical / representativeWhat the RBT judges as representative of the set.Subjective — varies by therapist, hardest to compare over time.

What you gain — and what this version gives up

Gained: correctness at a known support level — "G12, 80% at Gestural" — which is the pairing that drives programming decisions (90% at Gestural for five sessions → time to fade). Prompt-fading trends across sessions are fully preserved, and that is the trend used for insurance justification and for predicting mastery.  Given up: fading within a single set (trial 1 needed full physical, trial 5 independent) is not captured. That is a real loss, accepted deliberately in exchange for data the therapist can actually record accurately.

One addition we recommend — automatic timestamps (nothing changes for the RBT)

Today a goal's trial block records a date but no clock time. (Your ABC incidents already capture a time; trials don't.) We propose the app record automatically when each goal block was scored. This adds no step for the therapist — the app stamps each ✓/✗ tap by itself, invisibly, with nothing new on screen.
Why it matters later: to compare this data against session video (Phase 2), skeleton detection (Phase 3), or a wearable signal (Phase 4), we have to know when in the session a goal was run. With only a date, the closest possible match is the whole two-hour session — too coarse to correlate with anything. With a time, every session ever recorded becomes alignable to those later signals — thousands of goal blocks, not just the ~100 sessions that will eventually get video-annotated.

Decisions needed before we build

  1. Levels & order: is the six-level set above correct, in this order? Add Visual/Textual? Remove any?
  2. Meaning of the field: A, B, or C above? (We recommend A — target level.)
  3. Required or optional: must the RBT set a level on every goal they run? Blank must stay legal and must mean "goal not run today" — clearly different from "Independent / no prompt needed."
  4. Dropdown or buttons? A dropdown spells out "Gestural" but on an iPhone opens a scroll wheel that covers part of the screen (tap → scroll → confirm). A row of six small buttons in the goal header is a single tap, but shows only G. Same data either way — your call on which the RBTs will use more reliably.
  5. Mastery rule (this is f30b, below): should goal mastery stay at 80% × 5 consecutive sessions, or become 80% × 5 consecutive at Independent? If it changes, we also need your ruling on history: every session recorded before this ships has no level, and blank must be treated as unknown rather than not independent, or mastery would silently stop working for existing data.
  6. Smaller rulings:
    • Goal run in two different settings in one session — one level, or one per setting?
    • Baseline / probe trials, which are unprompted by definition — record "Independent," or flag separately?
    • May the level be corrected after the session is submitted?
    • Should prompt level appear on the parent/caregiver dashboard? (Our recommendation: no — "needed hand-over-hand support" is easy for a family to misread without context.)
  7. Automatic timestamps: please confirm you are comfortable with the app recording the time each goal block is scored (see the section above). No action and no extra step for the RBT — the app does it silently. Needed so this data can be aligned with video, skeleton, and wearable signals later.

How this lands on the roadmap — f30 splits in two

Splitting it the same way f26 was split, so the cheap, time-sensitive half isn't held up by the clinical decision in question 5.

Why the date matters: prompt level cannot be backfilled — no one can reconstruct what support Camila needed on G12 last March. The field only exists for sessions recorded after it ships. Phase 1.5 (the first behavioral model) trains on data through February 2027: shipping f30a in October yields about four months of prompt history to train on; shipping in December yields two, covering so few sessions that the model would learn the gap rather than the signal. Prompt level is also the best single predictor of the metric that phase is evaluated on — mastery timing — because today the data cannot distinguish 80%-with-full-physical-support from 80%-independent.
